**零代码 vs 低代码 vs 写代码 —— M1 阶段体感复盘**

在完成了名片页和双平台倒计时器的实战后，我对这三种开发形态有了具象的认知。

**零代码（Lovable / 美团 NoCode）** 胜在“快”和“美”。Lovable 的审美极具产品感，适合快速验证想法和交付 Demo。但它是黑盒，一旦逻辑复杂（如美团 NoCode 生成的 React 结构），维护成本陡增，且存在“幻觉”风险（如漏写定时器清理逻辑）。

**低代码（Trae SOLO/Builder）** 则是折中方案。AI 生成了 70% 的脚手架，但我必须介入剩下的 30%。例如在倒计时器中，我能看清 `setInterval` 和 `clearInterval` 的调用关系。这种“反哺”让我既享受了效率，又保住了对核心逻辑的控制权。

**写代码** 目前虽未大规模展开，但在调试 NoCode 生成的代码时，我深刻意识到：不懂原生 JS（如 Date 对象、DOM 操作），就无法甄别 AI 的“胡言乱语”。

**结论**：零代码是玩具，低代码是工具，写代码是根基。Vibe Coding 不是抛弃代码，而是为了更高效地驾驭代码。
